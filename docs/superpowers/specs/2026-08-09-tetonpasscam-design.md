# tetonpasscam.com — Technical Design

Date: 2026-08-09. Product requirements: `TETONPASSCAM-SPEC.md` (source of truth for product behavior; this doc records the technical decisions made with Drew for P1).

## Decisions made

| Decision | Choice |
|---|---|
| Hosting | Cloudflare, everything — single Worker project (Approach A) |
| Database | **Cloudflare D1** (SQLite) — Postgres requirement dropped for an all-Cloudflare stack |
| Email notifications | **Resend** free tier (3,000/mo) → drew@monroeresidential.com |
| Routes | 6 routes / 12 directions, including Jackson Hole Airport (see below) |
| Poller cadence | 10-min daytime (05:00–23:00 local), hourly overnight; seasonal tuning is config |
| Admin auth | Bearer token (`ADMIN_TOKEN` secret); Cloudflare Access possible later |

## Architecture

One Cloudflare Worker project. The Worker's `fetch` handler serves the built Vite frontend as static assets (SPA fallback) and the `/api/*` routes via **Hono**; the `scheduled` handler runs the poller and the nightly aggregation via two Cron Triggers. **Drizzle ORM** defines the D1 schema and generates SQL migrations applied with `wrangler d1 migrations apply`. One `wrangler deploy` ships everything.

```
tetonpasscam/
├── src/
│   ├── worker/
│   │   ├── index.ts     # fetch (API + assets) + scheduled (cron) entrypoints
│   │   ├── api/         # status, history, alerts, feedback, admin, camera-error
│   │   ├── poller/      # one module per source: wydot-status, wydot-weather,
│   │   │                #   google-routes, idaho511, detours; aggregate (nightly)
│   │   └── db/          # Drizzle schema + queries
│   ├── app/             # React + Vite + TypeScript + Tailwind frontend
│   └── shared/          # Types shared by worker & app
├── migrations/          # Generated by drizzle-kit, applied by wrangler
├── test/fixtures/       # Saved WYDOT HTML captures for parser tests
└── wrangler.toml
```

- Frontend: React + Vite + TypeScript + Tailwind, dark-mode via `prefers-color-scheme`. `index.html` is the prerendered SEO shell (title `Teton Pass Cam — Live Cameras, Conditions & Drive Times`, H1, meta, FAQPage schema, 100–150-word explainer — all present pre-hydration). `vite-plugin-pwa` for installability and the offline shell (last-cached status + prominent stale warning).
- Capacitor (P2) wraps the same `dist/`; no SSR or Node assumptions in app code.
- Cron: schedules are UTC — daytime window widened one hour each side to cover MST/MDT rather than encoding TZ logic in cron expressions. Nightly aggregation ~09:10 UTC.
- Secrets via `wrangler secret`: `GOOGLE_ROUTES_KEY`, `IDAHO_511_KEY`, `RESEND_KEY`, `ADMIN_TOKEN`. Never in repo or client bundle.

## Database schema (D1/SQLite)

```sql
routes(id, slug, name, origin_lat, origin_lng, dest_lat, dest_lng, direction)  -- 12 rows, seeded
travel_times(id, route_id, captured_at, duration_sec, static_duration_sec, distance_m, condition_snapshot)
route_typicals(route_id, weekday_class, hour, season, median_sec, p25_sec, p75_sec)  -- nightly rebuild
status_snapshots(id, captured_at, segment, status, condition_text, advisories, restrictions,
                 wydot_report_time, source)   -- status: open|restricted|closed|unknown
weather_snapshots(id, captured_at, air_f, surface_f, wind_avg, wind_gust, wind_dir, visibility_ft)
id33_events(id, captured_at, event_id, description, is_full_closure, cleared_at)
detour_snapshots(id, captured_at, route, condition_text)   -- US-26/US-89, only while CLOSED
alerts(id, created_at, expires_at, type, note, direction, device_hash, ip_hash, status)
feedback(id, created_at, body, email)
bans(device_hash, ip_hash, created_at)
```

Typicals dimensions: `weekday_class` = `weekday|weekend` (holidays counted as weekend later if warranted); `hour` = local hour 0–23 America/Denver; `season` = `winter` (Nov–Apr) | `summer` (May–Oct), matching the spec's seasonal cadence split.

Timestamps: ISO-8601 UTC text. Retention: `travel_times` forever (~45k rows/mo at 12 directions — trivial vs. D1's 10 GB); snapshot tables pruned at 2 years by the nightly job. Device/IP only as salted SHA-256 hashes; no PII beyond optional feedback email.

## Poller (each scheduled run)

Steps run independently — each try/caught so one source's failure never blocks another. Descriptive User-Agent on WYDOT fetches (`tetonpasscam.com poller (drew@monroeresidential.com)`); 30s timeouts; one retry with backoff on 5xx only.

1. **Status, primary:** `RoadClosures.html` → find `<tr>` containing literal `Between Wilson and the Idaho State Line` **by text match, never cell index** (rowspan hazard). Closure Reason `Road Open` → OPEN; closure language → CLOSED; chain law / no unnecessary travel / no trailers / high-profile → RESTRICTED (restriction text kept); fetch error / missing row / unrecognized shape → UNKNOWN. Retries resolve toward UNKNOWN, never OPEN. Parse `Last Report Time` (America/Denver), stored separately from `captured_at`.
2. **Fallback/cross-check** (only on primary failure or ambiguity): `WRR.RoutesResults?SelectedRoute=WY22` (closed ⟺ `CLOSED` in Conditions; capture District 3 WY22 comments); disagreement → `MEDIA.Statewide`; unresolved → UNKNOWN.
3. **Advisories:** diffed against previous snapshot; standing advisories (e.g. `Falling Rock`, standing all summer 2026) are background state — display always, event only on change.
4. **Weather:** `Sensors.StationResults?SelectedStation=Teton+Pass` → `weather_snapshots`.
5. **Drive times:** Google Routes `computeRoutes`, `TRAFFIC_AWARE`, per route-direction, 05:00–23:00 local only.
6. **Idaho 511:** one events call/cycle (throttle: 10/60s allowed, we use 1); `RoadwayName` containing `33` near Victor; `IsFullClosure` events → `id33_events`. Never affects the pass banner.
7. **When CLOSED:** fetch `WRR.RoutesResults` for US26 + US89 → `detour_snapshots`.

A `status_snapshots` row is written every cycle, including UNKNOWN — "last confirmed open at 5:48 PM" derives from the newest non-UNKNOWN row. **Never integrate `map.wyoroad.info/wti511map-data/*.pbf`.**

Staleness is computed at read time in `/api/status`, not stored: WYDOT report time >12h old (tunable by season) → stale flag alongside status; newest snapshot >2h old (poller dead) → status forced to UNKNOWN.

## Public API (edge-cached ~60s except POSTs and admin)

- `GET /api/status` — everything the Home screen needs in one call: status + staleness + WYDOT report time + restriction/advisory text; latest weather; latest travel time per direction with typical-for-now delta (delta omitted until ≥2 weeks of history); active ID-33 advisory; detour conditions when CLOSED; active alerts.
- `GET /api/history?route=<slug>` — typicals band (median/p25/p75 by hour, weekday-class, season) + today's actuals. Ships in P1; History screen consumes it in P2.
- `POST /api/alerts` — type (`crash|slideoff|slick|wildlife|stopped|closure|other`) + optional ≤140-char note + direction. Honeypot field; 2 reports/device/30min (device = random localStorage UUID, hashed server-side); IP throttle; ban-list check; small profanity wordlist. **Community reports never alter official status**; "closure" reports display as "unconfirmed — check 511".
- `GET /api/alerts` — active only; expiry: crash/stopped 2h, slick/wildlife 3h, closure 1h.
- `POST /api/feedback` — body + optional email → D1 + Resend email.
- `POST /api/camera-error` — beacon from camera onerror; Resend email throttled to 1/day/camera.
- `/api/admin/*` — bearer `ADMIN_TOKEN`: list/delete alerts, ban device/IP hash, list feedback.

## Frontend (Home screen, top to bottom)

1. Status banner — OPEN (green) / RESTRICTED (amber, restriction named) / CLOSED (red) / UNKNOWN (gray, Wyoming 511 link). Always shows WYDOT last-report time. CLOSED copy: "Closed — do not attempt. Traveling a closed Wyoming road is illegal (up to $750 fine)." Never invented reopening estimates. When CLOSED: detour block (US-26/US-89 via Swan Valley–Alpine, ~85 mi / ~1h40 typical, live detour conditions).
2. Drive-time rows — current vs typical (green/amber/red delta, hidden until 2 weeks of data), direction flip toggle.
3. Community alerts strip — type icon, age, direction, note, "Unverified community report" label. Empty state: "No reports in the last 3 hours."
4. Three WY-22 cams — timestamped, linked to WYDOT, attributed "Imagery: WYDOT Wyoming 511". Image URLs from tetonflats.com's webcam pages (Drew to supply); onerror → "View on Wyoming 511" link card + admin beacon.
5. Summit weather strip — air temp, surface temp (prominent in winter), wind avg/gust/direction, visibility.
6. Persistent "⚠ Report conditions" button → 2-tap modal (7-type grid, optional note + direction). No accounts.
7. Sponsor block → `https://tetonflats.com/?utm_source=tetonpasscam&utm_medium=referral&utm_campaign=sponsor`.
8. Footer — Wyoming 511, Idaho 511, START bus, 511 Notify recommendation, privacy policy, feedback link, "Not affiliated with WYDOT".

## Testing

- **Parsers (the critical surface):** Vitest against `test/fixtures/` — real captures of RoadClosures.html (open / closed / restricted), the rowspan trap, valley-segment-only confusion, mangled/empty page → UNKNOWN, sensor page, Statewide page. Fixtures captured before implementation.
- **API:** Hono test client + local D1 (miniflare): rate limiting, honeypot, ban enforcement, expiry filtering, staleness → UNKNOWN degradation, admin auth.
- **Live-shape check:** a manually-run script fetches live WYDOT pages and asserts the parser still recognizes them (not in CI — polite to WYDOT).
- **Pre-launch (spec definition of done):** curl checks for title/H1/meta; kill poller → UNKNOWN within 2h; POST /api/alerts rate-limits; Lighthouse mobile ≥ 90; `npx cap sync` clean.
